Identity and working-context files. Small, stable, high leverage: every session reads `me.md`, so a line here shapes every interaction.

## Files

- `me.md`: the owner's profile. Update in place when a preference, habit, or fact about the owner changes. Never let it grow into a journal; dated events go to `Daily/`.
- `strategy.md`: goals and priorities. Rewrite to present-tense truth when goals change rather than appending dated corrections.
- `infrastructure.md`: tools, integrations, and an "External Codebases" table mapping each project to the path of its code repo. A project's runnable code never lives in the vault; this table says where it does live.

## Rules

- A fact about the owner (preference, habit, taste) goes to `me.md`, not to a rule in the root `CLAUDE.md`. Rules are about how the agent works; `me.md` is about who it works for.
- Files here are current-state documents, not ledgers. Replace stale claims in place.
- Keep `me.md` under roughly a hundred lines. If it is longer, something in it belongs elsewhere.
